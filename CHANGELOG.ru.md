## [1.0.0] - 2026-10-13 🎉

Первый публичный выпуск.

### ✨ Added

**🪟 Views**

- Единая вкладка просмотра, которая переиспользуется для любого файла, вида и члена: переключатель
  вида (`IL code`, `C# (high level)`, `C# (low level)`, `Native ASM`) и переключатель области (весь
  файл или один член) работают через CodeLens-строку над кодом и через строку состояния.
- Листинг IL целого файла, типа или члена: полный вывод `.class`/`.method` с локальными переменными и
  обработчиками исключений.
- Аннотации sequence points прямо в IL (`// sequence point: (line 18, col 13) …`) с кликабельными
  ссылками в исходный файл.
- Декомпилированный C# в двух видах: высокоуровневом — как код был написан, и низкоуровневом — как его
  сделал компилятор, вместе со сгенерированными членами.
- Свойства и события показываются как свойства, а запрошенный аксессор назван в списке областей.

**🔗 Mapping**

- Точная связка IL ↔ строка исходника по portable PDB, причём идентификатор PDB сверяется со сборкой:
  PDB от другой сборки игнорируется, а не ломает вид.
- Двусторонняя подсветка и прокрутка между исходником, панелью IL и панелью C#; там, где у вида нет
  данных об исходнике, связка работает на уровне метода.
- Узлы дерева разрешаются через `map/fileOf`, поэтому клик по типу или члену открывает исходник с
  кареткой на нём и просмотрщик рядом — включая типы, тела которых лежат в сгенерированных
  конечных автоматах.

**🔬 Native code**

- Листинг JIT через собственный харнесс расширения (`DOTNET_JitDisasm` + `RuntimeHelpers.PrepareMethod`)
  — оптимизированный (`FullOpts`) или tier 0, без выполнения тела метода.
- Attach к живому .NET-процессу (ClrMD): ровно тот код, который процесс исполняет сейчас, метка
  `IL_xxxx` у каждой инструкции и переход из инструкции в её строку исходника.
- Чтение образов ReadyToRun без процесса, включая arm64-образы на x64-машине (Capstone), с картой
  «инструкция → IL», разобранной из секции `DebugInfo`. Читаются обе кодировки: упакованная (16.0) и
  старая ниббловая (9.1).
- Образы NativeAOT: контейнер ELF, символы и DWARF дают машинный код метода, его строки исходника и
  связку, работающую в обе стороны.
- Публикация одним файлом: бандл распаковывается, и все управляемые виды продолжают работать — включая
  сжатые self-contained бандлы.

**🧰 Tooling**

- Round-trip через ILASM: весь листинг выписывается, собирается обратно `ilasm` и сравнивается с
  оригиналом. Ассемблер поставляется с расширением для linux-x64/arm64, osx-x64/arm64 и win-x64.
- Боковое дерево текущего файла и сборок проекта с ленивой загрузкой, плюс `ilasmDotnet.assemblies`
  для сборок и нативных образов вне воркспейса.
- Автопоиск выходной сборки для открытого исходника (`.csproj`, `.fsproj`, `.vbproj`, `bin/**`),
  покрывающий обычные сборки, `PublishAot` и публикацию одним файлом.
- `Show Diagnostics`: версии, пути, настройки, состояние PDB, состояние attach и то, что показывает
  вкладка.
- Внятный диагноз вместо `Unknown file format.` для нативных файлов (ELF, Mach-O, нативный PE) и
  пояснение, когда ReadyToRun-образ прочитать нельзя.

**🧩 Languages**

- F#, VB и любой другой язык .NET: просмотрщик читает сборку, поэтому файл `.fs` или `.vb` открывает
  свой IL и ссылается обратно на строки в `.fs`/`.vb`.

### 📌 Notes

- Требуется VS Code 1.90 или новее и **.NET 10 runtime**; более новый рантайм тоже подойдёт
  (`RollForward=LatestMajor`). Версия VS Code поднята до 1.105 в невыпущенных изменениях выше.
- Расширение не делает сетевых запросов и не собирает телеметрию: каждый вид считается локально
  поставляемым движком на .NET.
